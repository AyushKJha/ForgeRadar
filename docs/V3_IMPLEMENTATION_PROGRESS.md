# ForgeRadar V3 implementation progress

Status is based on code and tests, not design intent. V3 has not been deployed or pushed.

- [x] Phase A — Audit & stability. Audit, architecture, inventory, risk log and recovery procedure written. `backup.mjs` created and a live-data snapshot verified by checksum and SQLite integrity. The daily launcher now uses process-local PowerShell script permission and exits cleanly without duplicate work. Baseline tests: 20/20 passed.
- [x] Phase B — Local free foundation. Versioned SQLite migrations provide job history, a durable pending-command queue and 24-hour source cache. Pending commands resume once after restart; claimed work becomes interrupted and requires review. The next collection time persists. Settings shows actual job/model/source diagnostics and opt-in OpenAlex/Crossref records with separate publication/retrieval dates. Local Ollama remains sequential; low-memory runs are blocked, and existing heuristic discovery/manual planning still work without it. Existing cached data remains available offline. arXiv, full source-wide opt-in controls and advanced manual development remain for later phases.
- [x] Phase C — Local multi-user accounts with isolated profiles, consented manual interests, reviewed PDF/DOCX suggestions, public GitHub portfolio selection, export and deletion. Owner-only legacy APIs remain protected. Remote member access and richer provenance review remain for later phases.
- [ ] Phase D — Discovery intelligence. In progress: per-user research feed applies a hard selected/excluded-domain filter, offers six explicit modes and mode weights, separates publication from retrieval age, explains heuristic weights, and has an honest empty state. Manual opt-in OpenAlex/Crossref scans send only selected domain names. Account-scoped save/dismiss/restore and 2–5 source comparison work. Related-work view searches locally cached research titles and GitHub repository signals, with limited-coverage disclosure. Fuller battle criteria, feedback learning and skill gap remain.
- [ ] Phase E — Project studio, tasks and agents. In progress: source-grounded or user-defined local proposal drafts are editable and require an explicit approval action; saving/approving does not start a build or create a repository. Approved proposals support account-scoped persistent manual tasks with create/edit/status/delete and acceptance/evidence gating. Review-only suggestions use a selected installed local Ollama model, a 120-second timeout, five-task limit, duplicate filtering and a free-RAM guard. A real qwen3:4b smoke run produced suggestions but omitted one rationale, so the UI now exposes that omission; a second run was blocked at 1.0 GiB free RAM by the 1.2 GiB guard. Repeat successful end-to-end validation, typed dependencies, architecture canvas and agent execution integration remain.
- [ ] Phase F — Validation evidence and protected remote access.
- [ ] Phase G — Explicit public publication workflow.
- [ ] Phase H — Nebula and Sunset product experience. Both themes have semantic tokens, responsive onboarding/login/discovery styles, a per-user persisted switch, instant application and reduced-motion control. The rest of the workspace, constellation, journey, previews and mobile polish remain.
